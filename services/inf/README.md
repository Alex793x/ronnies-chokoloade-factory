## Where am I?

This stack lives at **`services/inf/`** inside the `ronnies-chokoloade-factory`
monolith. Run every command below from this directory. CI, CODEOWNERS and
governance are owned by the repository root — the smart pipeline
(`.github/workflows/ci.yml` at the root) runs this stack's checks only when
`services/inf/**` or a shared path changes. The full service index is in
`keel.services.json` at the root.


## What is this?

A Terraform skeleton for Azure (**azurerm ~> 4.0**, Terraform **>= 1.7**):

- `main.tf` — provider pinning, the `local.name_prefix` naming convention
  (`ronnies-chokoloade-factory-<environment>`), platform default tags, and the stack's
  root resource group (`rg-ronnies-chokoloade-factory-<environment>`).
- `variables.tf` — `environment` (validated against `dev`/`staging`/`prod`,
  mirroring the branch model), `location`, extra `tags`.
- `outputs.tf` — the root resource group's name/id/location for downstream
  stacks.

Grow the stack by adding resources that reuse `local.name_prefix` and
`local.default_tags` — never hand-name or hand-tag resources.

## Quickstart

```bash
terraform init -backend=false   # offline: providers only, no state backend
terraform fmt -check -recursive # formatting gate (run `terraform fmt` to fix)
terraform validate              # schema + reference validation
terraform plan -var environment=dev   # needs Azure credentials + a backend
```

## State & backends

State is **never** committed. Until a remote backend is configured, only
`init -backend=false` / `validate` are meaningful (that is exactly what CI
runs). Before the first real `apply`:

1. Provision the platform state storage (resource group + storage account +
   `tfstate` container) once per environment.
2. Uncomment and fill the `backend "azurerm"` block in `main.tf`; keep one
   state `key` per environment (`ronnies-chokoloade-factory.<environment>.tfstate`).
3. Run `terraform init` (with the backend) per environment; promote changes
   dev → staging → prod, matching the branch model.

Commit `.terraform.lock.hcl` when it appears — provider pins are part of the
review surface.

## CI

The commands above are wired into the root smart pipeline per service — no
`.github/` directory exists at this level on purpose.


## Standards

- Derive every resource name from `local.name_prefix`; never hardcode names.
- Merge `local.default_tags` into every taggable resource (`var.tags` is for
  stack-specific additions).
- Constrain new variables with `validation` blocks — invariants live in the
  code, not in tribal knowledge.
